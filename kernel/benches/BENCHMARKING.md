# Delta Kernel Benchmarking Guide

This guide covers the complete benchmarking system for Delta Kernel, including dataset generation, running benchmarks, and analyzing results.

## Overview

The benchmarking system consists of three main components:

1. **Dataset Generation** (`generate_datasets.sh`) - Creates test Delta tables with various configurations
2. **Benchmark Runner** (`run_all_benchmarks.sh`) - Executes all benchmarks against generated datasets
3. **Results Analysis** (`analyze_benchmark_results.sh`) - Analyzes and compares benchmark results

## Quick Start

```bash
# From the kernel/benches directory

# 1. Generate test datasets (one-time setup)
cd add_action_generator
./generate_datasets.sh

# 2. Run all benchmarks (from kernel/benches)
cd ..
./run_all_benchmarks.sh

# 3. Analyze results
./analyze_benchmark_results.sh
```

## Dataset Generation

### Script: `add_action_generator/generate_datasets.sh`

Generates Delta tables with different deletion vector (DV) percentages and content root configurations.

**Usage:**
```bash
./generate_datasets.sh [output_dir]
```

**Generated Datasets:**

| Dataset | DV Percentage | Content Root | Description |
|---------|---------------|--------------|-------------|
| `dv_0_pct` | 0% | No | Baseline table without deletion vectors |
| `dv_0_pct_with_content_root` | 0% | Yes | Baseline table with content root enabled |
| `dv_50_pct` | 50% | No | Half of files have deletion vectors |
| `dv_50_pct_with_content_root` | 50% | Yes | 50% DVs with content root |
| `dv_100_pct` | 100% | No | All files have deletion vectors |
| `dv_100_pct_with_content_root` | 100% | Yes | 100% DVs with content root |

**Default Configuration:**
- 50,000 actions per dataset
- 20 sidecar files
- Random seed: 42

## Running Benchmarks

### Script: `run_all_benchmarks.sh`

Executes a comprehensive benchmark suite against all generated datasets.

**Usage:**
```bash
./run_all_benchmarks.sh [datasets_dir] [results_dir]
```

**Arguments:**
- `datasets_dir` - Directory containing generated datasets (default: `datasets`)
- `results_dir` - Directory to store results (default: `benchmark_results`)

**Benchmark Workflow:**

For each dataset, the script runs three phases:

#### Phase 1: Pre-DML Scans
- Full table scan (enumerate all tasks and files)
- Needle-in-haystack query (selective filter on partition_id=1)

#### Phase 2: DML Operations
- Small write (5 files, non-bulk mode)
- Small write (5 files, bulk mode)
- Bulk write (1000 files, 500 batch size, non-bulk mode)
- Bulk write (1000 files, 500 batch size, bulk mode)
- Vacuum delete (partition threshold=5, non-bulk mode)
- Vacuum delete (partition threshold=5, bulk mode)

#### Phase 3: Post-DML Scans
- Full table scan (after DML operations)
- Needle-in-haystack query (after DML operations)

**Output Structure:**
```
benchmark_results/
└── run_YYYYMMDD_HHMMSS/
    ├── summary.json              # Aggregated results in JSON
    ├── summary.txt               # Human-readable summary
    ├── analysis.txt              # Generated by analysis script
    ├── dv_0_pct/
    │   ├── 01_pre_scan_full_table.json
    │   ├── 02_pre_scan_needle.json
    │   ├── 03_dml_small_write.json
    │   └── ...
    ├── dv_50_pct/
    │   └── ...
    └── ...
```

## Analyzing Results

### Script: `analyze_benchmark_results.sh`

Analyzes benchmark results and generates comparison reports.

**Usage:**
```bash
./analyze_benchmark_results.sh [results_dir] [run_id]
```

**Arguments:**
- `results_dir` - Directory containing benchmark results (default: `benchmark_results`)
- `run_id` - Specific run to analyze (default: most recent run)

**Analysis Output:**

The script generates `analysis.txt` containing:

1. **Pre-DML Scan Metrics** - Performance before any modifications
2. **DML Operation Metrics** - Write/delete performance
3. **Post-DML Scan Metrics** - Performance after modifications
4. **Content Root Comparison** - Impact of content root on performance
5. **Bulk Mode Comparison** - Bulk vs non-bulk mode performance
6. **Key Findings** - Summary statistics and fastest/slowest operations

**Example Analysis Output:**

## Benchmark Scenarios

### Full Table Scan
Enumerates all scan tasks and counts files, measuring:
- Time to first task
- Time to enumerate all tasks
- Number of tasks, files, and DV descriptors

### Needle in Haystack
Selective query with a filter predicate (partition_id = 1), measuring:
- Query performance with filtering
- Number of files pruned
- DV descriptor handling with predicates

### Bulk Write
Inserts many files in batches, comparing:
- Batch commit mode (content root)
- Non-batch commit mode (standard Delta)
- Transaction duration
- Commit success rate

### Small Write
Inserts a small number of files (5), measuring:
- Overhead of write operations
- Performance difference between bulk and non-bulk modes

### Vacuum Delete
Deletes up to 50,000 files based on a partition threshold, measuring:
- Large-scale delete performance
- Impact of bulk mode on delete operations
- Transaction commit time

## Metrics Collected

### Scan Metrics
- `time_to_first_task_ms` - Latency to start scanning
- `time_to_enumerate_all_tasks_ms` - Total enumeration time
- `num_tasks` - Number of scan tasks generated
- `num_files` - Total files scanned
- `num_dv_descriptors` - Number of deletion vectors encountered
- `total_bytes` - Total data size (when available)

### Write Metrics
- `transaction_duration_ms` - Time from txn init to commit
- `num_files_written` - Files added to the table
- `total_bytes_written` - Total data written
- `commit_succeeded` - Whether commit completed successfully

### Overall Metrics
- `total_duration_ms` - End-to-end operation time
- `scenario` - Name of the benchmark scenario
- `table_path` - Path to the Delta table

## Performance Comparison

### Content Root Impact
Content root (metadataTree-experimental feature) enables:
- Batch commits for faster write operations
- Efficient metadata tree structure
- Reduced checkpoint size

**Expected Performance:**
- Faster bulk writes (5-10x improvement)
- Comparable scan performance
- Better scalability for large tables

### Bulk Mode vs Non-Bulk Mode
Bulk mode uses batch commits with parallel leaf node creation:
- **Bulk mode**: Creates leaf manifests in parallel, single commit
- **Non-bulk mode**: Sequential commits per batch

**Expected Performance:**
- Bulk mode: Faster for large operations (10-100x)
- Non-bulk mode: Lower memory overhead

### DV Percentage Impact
Deletion vectors affect scan performance:
- 0% DVs: Baseline performance
- 50% DVs: Moderate overhead for DV processing
- 100% DVs: Maximum DV processing overhead

## Requirements

- Rust toolchain (cargo)
- `jq` (for result analysis)
- ~10GB free disk space for datasets
- AWS_LC_SYS_CMAKE_BUILDER=1 environment variable (set automatically by scripts)

## Tips

1. **Run benchmarks on a quiet system** - Background processes affect timing
2. **Use consistent hardware** - Compare runs on the same machine
3. **Check dataset integrity** - Verify datasets generated correctly before benchmarking
4. **Multiple runs** - Run benchmarks multiple times to account for variance
5. **Monitor resources** - Watch memory/CPU usage during large operations

## Troubleshooting

### Dataset Generation Fails
- Check disk space (need ~10GB)
- Ensure cargo build succeeds
- Verify backfill-delta-table binary builds

### Benchmark Fails
- Check dataset exists at expected path
- Verify benchmark-runner binary built successfully
- Review error output in result JSON files

### Analysis Shows N/A Values
- Install `jq` for proper JSON parsing
- Check that benchmark actually ran and produced output
- Verify JSON files are valid

## Example Workflows

### Quick Performance Check
```bash
# Generate minimal datasets
./add_action_generator/generate_datasets.sh test_datasets

# Run only scan benchmarks on one dataset
./target/release/benchmark-runner \
    -t file://$(pwd)/test_datasets/dv_50_pct \
    full-table-scan
```

### Full Benchmark Suite
```bash
# Generate all datasets (once)
./add_action_generator/generate_datasets.sh production_datasets

# Run complete benchmark suite
./run_all_benchmarks.sh production_datasets results

# Analyze results
./analyze_benchmark_results.sh results
```

### Compare Two Runs
```bash
# Run baseline
./run_all_benchmarks.sh datasets baseline_results

# Make code changes...

# Run comparison
./run_all_benchmarks.sh datasets comparison_results

# Analyze both
./analyze_benchmark_results.sh baseline_results run_*
./analyze_benchmark_results.sh comparison_results run_*

# Compare manually using diff or custom script
diff baseline_results/run_*/analysis.txt comparison_results/run_*/analysis.txt
```

3. Add benchmark run to `run_all_benchmarks.sh`
4. Update analysis script to parse new metrics
5. Document in this file
